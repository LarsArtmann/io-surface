io-surface is a hermetic, deliberately-minimal gate CLI: a stdlib-only AST walk, an in-process CUE load, findings to stdout, exit 0/1/2. That shape decides every verdict below. The two adopted libraries (cmdguard 93/100, go-atomic-write 80/100) are used at or near their ceiling for this kind of tool. Two more (go-error-family, go-output) are already compiled into the binary via go-finding and cmdguard, and are still correctly left unimported. Everything else is server, CQRS, UI, or lifecycle machinery for a process io-surface deliberately is not.

01Findings

The dependency doctrine is winning

Four direct dependencies for a tool that parses Go trees, unifies CUE, and emits SARIF — and the two house libraries among them are used at or near their ceiling. cmdguard usage covers the full core surface (typed flags, batteries, parent commands, positional args, consumer-owned exit codes); go-atomic-write usage includes the advanced optimistic-concurrency path (FingerprintFromBytes + WriteVerified + ErrConcurrentModification handling) on both in-place rewrite paths.

Two free patch bumps are pending

cmdguard v4.2.0 → v4.2.1 (fixes ExitCode(0) on errorfamily failures and flag leaks on reused CLIs) and go-atomic-write v0.6.0 → v0.6.2 (v0.6.1 stops temp-file leaks when the final rename fails). No API changes in either gap; both are pure hygiene. See Actions.

Zero-cost availability is not a reason to adopt

go-error-family and go-output are already in the module graph (via go-finding and cmdguard), so importing them adds no new module. Both reports still conclude do not adopt: error-family's exit codes would break the pinned 0/1/2 contract, and go-output would churn byte-pinned golden output for no requested capability.

Strengths

+
Every write is atomic, both in-place rewrites are concurrency-guarded Five write sites, zero raw file writes; the baseline-add path even remaps ErrConcurrentModification into a domain error with re-run guidance (internal/manifest/baseline_write.go:63).
+
The exit-code contract stays owned by the tool cmdguard prints errors once; io-surface maps 0/1/2 itself (cmd/io-surface/main.go:39-51) and pins it in tests — the reason error-family's exit codes were rejected, not overlooked.
+
Tool-to-target relationships instead of couplings go-cqrs-lite, go-appkit and httputil appear in the extractor's classification tables, not its go.mod — io-surface understands the fleet without depending on it.
