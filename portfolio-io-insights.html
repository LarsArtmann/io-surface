03Insights

Gate readiness: 1 of 182 projects already declare their I/O surface

These repos carry docs/architecture/io-surface/facts.cue and pass io-surface check in CI. The other 181 could onboard with one init run each; the extractor already parsed them without errors in this scan.

io-surface

file-read dominates: 1,675 sites (28% of classified production sites)

The fleet's single biggest I/O surface is file-read, led by os.Stat with 825 sites across 98 projects. Environment access is the other universal touchpoint: 631 sites touch env (Getenv/LookupEnv/Setenv/Environ). These are exactly the surfaces an I/O manifest makes reviewable and review-before-merge.

The advisory tier is real: 1,941 token-confidence sites (32% of production sites)

These were caught by method-name heuristics on unresolvable receivers (ListenAndServe, Dial, ExecContext, ...) rather than resolved imports. A real gate must treat them as advisory (facts.extractable: false), never build-breaking. The resolved tier in this scan: 4,130 sites.

89 projects open sockets: listeners or outbound dials

Heaviest network surface: templ (24), go-taskqueue (21), pbx-artmann (18), BuildFlow (12), BuildFlow-pr44 (12). Everything else on this machine talks mostly to files and environment.

Databases, subprocesses, and crypto

48 projects touch databases (sql.Open, cqrs engines, QueryContext tokens), 65 spawn subprocesses (exec.Command, LookPath), and 43 consume cryptographic entropy (crypto/rand, rsa.GenerateKey, x509.CreateCertificate), which is the family most worth pinning down in a review.

entropy users: AutoCart, BerryBig, BuildFlow, BuildFlow-pr44, ChastityAPI, Cyberdom, DiscordSync, GmbH, Rolls-Royce-mtuGoHelpCenter-golang, StopTube and 33 more

60% of all extracted sites live only in tests

9,221 of 15,292 sites are in _test.go or testutil/ files. The gate excludes tests by design, so manifests stay small; this scan includes them to show how much I/O exists only under test.

18 fixture sites filtered out

Locations under testdata/ or docs/ packages were dropped after extraction; they are fixtures, not authored I/O. Generated files (*_templ.go, *.pb.go, zz_generated*, stringer output) were never parsed.

11 Go projects with code but zero production I/O sites

These have production Go files yet nothing the extractor watches fires: pure libraries, spec/codegen repos, or I/O hidden behind unresolvable seams. They are the cheapest possible init wins: an almost-empty manifest.

accounting-pitch-deck, go-codec, go-composable-business-types, go-must, go-ndjson, go-policy-dsl, go-retry, setup-github-repo, template-CONTRIBUTING, template-air, template-github-actions

06Methodology

1

Discovery

pma list -o json over ~/projects produced 182 projects (cached discovery snapshot, 2026-11-07).

2

Extraction

io-surface v0.2.0 internal/extract: a hermetic stdlib AST walk (go/parser + ast.Inspect, no go/packages, no network) parsed every top-level Go directory of each project. vendor, node_modules, and dot-directories were skipped. Test files (*_test.go and testutil/ packages) were parsed and classified as test-only sites; the production numbers exclude them.

3

Filtering

Generated code was ignored before parsing (*_templ.go, *.pb.go, zz_generated*, *_string.go, *_gen.go, deepcopy, easyjson). After extraction, locations under testdata/ or docs/ packages were dropped (18 locations).

4

Classification

Resolved tier: package-qualified calls through imports (os.ReadFile, http.Get, sql.Open, ...) - the only tier that can fail a real gate. Token tier: method-name heuristics on unresolvable receivers (ListenAndServe, Dial, ExecContext, .Do) - advisory by design, attributed to the enclosing symbol.

5

Aggregation and rendering

Per-project counts were folded into fleet totals, ranked, and rendered into this single self-contained HTML file (no JS dependencies beyond the template's optional scrollspy). The full machine-readable result is at /tmp/io-surface-portfolio-stats.json.

Reading the numbers Counts are call-site level, not occurrences: a symbol calling os.ReadFile three times is one site with one call.
