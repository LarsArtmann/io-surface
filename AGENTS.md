# AGENTS.md

`io-surface` is the I/O surface manifest gate: a Go CLI that extracts every I/O
call site from a Go tree via a stdlib-only AST walk, compares it against a CUE
manifest, and fails the build on I/O nobody documented — AND (since v0.3.0,
io-bug-radar) a detector layer that finds bad I/O via `io-surface lint`
(manifestless, exit 0 unless `--enforce`; rules ship at info, promotion is
evidence-gated). Single Go module (`go 1.27`), four direct dependencies
(`cuelang.org/go` for the manifest, `cmdguard/v4` for the CLI, `go-finding`
for SARIF, `go-atomic-write` for the tool's own file writes — the gate core
`internal/extract` itself stays stdlib-only), no
`flake.nix` (deliberately withheld — status report §g-Q2), no Makefile/justfile.

`README.md` documents the tool for users. This file documents the repo for
agents working ON the tool.

## Commands

```bash
go build ./...                          # build
go vet ./...                            # vet
go test ./...                           # tests (fast, hermetic)
go test -cover ./...                    # with coverage
gofmt -l .                              # must print NOTHING (CI gate)
go run ./cmd/io-surface check --root .  # SELF-HOSTING GATE (CI runs exactly this)
go run ./cmd/io-surface render --root . # render must not crash (CI checks)
go run ./cmd/io-surface lint --root .   # detector radar (report-only; CI emits SARIF artifact)
```

CI (`.github/workflows/ci.yml`): build → vet → test → gofmt gate → self-check
→ facts-freshness (`init --force` + filtered `git diff`) → self-render →
inventory-doc freshness (`render --doc … --check`) → SARIF emit → lint-radar
SARIF (artifact-only, implements the TODO #61 policy — advisory, no
enforcement until D4 promotion). That is the
whole quality bar. `CONTRIBUTING.md` mentions
`golangci-lint` but there is no `.golangci.yml` and CI does not run it.
`dprint.json` exists for non-Go files (markdown/yaml/json) but CI does not
enforce it.

The `.gitignore` has a `>>> buildflow-managed >>>` block — never hand-edit
inside those markers; it is regenerated by `buildflow --fix`.

## Remotes & mirrors

Two remotes, house convention (same as gogenfilter etc.):

```text
origin  ssh://forgejo@forgejo.home.lan/lars/io-surface.git   # primary (Forgejo on evo-x2)
github  git@github.com:LarsArtmann/io-surface.git            # public mirror
```

- Branches track `origin`. `master` is the default branch; CI runs on
  `main`/`master` pushes **on GitHub** (Forgejo does not run the workflow).
- Until a server-side push mirror is configured in the Forgejo UI (Settings →
  Mirrors → push mirror to `github.com/LarsArtmann/io-surface`, as gogenfilter
  has), every publish must push BOTH remotes:
  `git push origin master && git push github master` — the auto-commit daemon
  creates commits, it does not push.
- GitHub is **public** deliberately: the module path
  (`github.com/larsartmann/io-surface`) makes the README's
  `go install …@latest` require a public GitHub repo. Do not make it private.
- The Forgejo repo was push-created and defaults to **private**; if it should
  be public (as gogenfilter is), flip it in the Forgejo UI — repo creation and
  visibility changes need a Forgejo API token that is not on this machine.

## Self-hosting: editing Go code updates the gate contract

This repo is gated by its own tool. The committed manifest
(`docs/architecture/io-surface/{facts,claims,baseline,schema}.cue`) is a
snapshot of the tree. Consequences of touching any `.go` file under `cmd/` or
`internal/`:

- **Added an I/O call** (`os.ReadFile`, `http.Get`, …) → next `check` reports
  `undeclared-site` (error severity) → CI fails. Declare the site in
  `facts.cue` (or `claims.cue`).
- **Moved lines around** in a file that has declared sites → `location-drift`
  (info only, does NOT fail CI). Such infos are tolerated by design.

To refresh facts after an I/O-adding change:

```bash
go run ./cmd/io-surface init --root . --force
```

`init --force` is safe since 2026-11-06: it refreshes ONLY `facts.cue`
(`internal/scaffold/scaffold.go` `Write` skips any judgment/standard file that
already exists). `claims.cue`, `baseline.cue` and `schema.cue` are never
overwritten by a refresh — guarded by the plant-a-claim test
(`TestWrite_ForceRefreshesFactsOnly`).

## Architecture

Data flow: `cmd/io-surface` (flag dispatch) → `internal/extract` (AST walk) →
either `internal/scaffold` (`init`: write snapshot) or `internal/check`
(`check`: pair extraction against `internal/manifest` load, emit findings) →
`internal/render` (`render`: manifest → markdown).

Version const lives here.                                                                                                                                                                                                                                                                                                                                                 |

### Where detection rules live

Everything the extractor "knows" is hardcoded tables in
`internal/extract/extract.go`:

- `pkgOf` / `importSubstring` — import path → classification key
- `callFamily` — package-qualified calls → family (**resolved** tier, can fail builds)
- `methodToken` — method-name heuristics on unresolvable receivers (**token** tier, advisory only)
- `seamIdent` — same-package wrapper identifiers (e.g. `atomicWriteFile`)
- `familyPrecedence` — dominant-family ordering

Teaching the extractor a new call = edit these tables + add a case to the
`testdata/extract` fixture. Type-fact resolution (interface dispatch,
cross-package method sets) is out of scope BY DESIGN: such sites get
`facts.extractable: false` in the manifest instead.

### Invariants that must stay in sync

- The 10 families and 7 disciplines exist in THREE places: the CUE closed
  enums in `internal/scaffold/schema.cue`, the `Families`/`Disciplines` vars in
  `internal/manifest/manifest.go`, and README prose. A new family is a schema
  version bump, not a casual edit.
- The manifest dir constant exists ONCE: `manifest.Dir` (scaffold aliases it).
- Schema is v1.2: `claims.criticality` ("low|normal|critical", default
  materializes on unification) and `claims.durability`
  ("ephemeral|recoverable|durable"). The deployed copy
  (`docs/architecture/io-surface/schema.cue`) must stay byte-identical to
  `internal/scaffold/schema.cue`; pilot repos carry their own copies
  (InboxClean is on v1.2, dnsblockd still v1 — its migration is an owner
  decision).
- The capability vocabulary exists in TWO places that must not drift: the
  `#CapabilityName` CUE enum in `internal/scaffold/schema.cue` and the
  closed enum + capability→families mapping in `internal/capability`. The Go
  package is the single-source mapping — rules and absorb derive from it.
  New capability names = schema version bump + ROADMAP Q5 decision.
- `capabilities.cue` is written ONLY by `absorb`; the hermetic gate never
  runs the reachability engine (check reads the manifest, never engine
  artifacts — `capability-drift` is emitted by `absorb --check`, not by
  `check`). Capslock in CI is installed with the repo's own Go toolchain:
  a version-skewed analyzer fails to type-check the target's stdlib.
  Schema copies (`internal/scaffold/schema.cue` ↔
  `docs/architecture/io-surface/schema.cue`) must stay byte-identical;
  `init --force` never refreshes them, so a schema change updates both by hand.
- Rule constants in `internal/check/check.go` (`RuleUndeclared`, …) are a
  stable contract — they become SARIF ruleIds and suppression keys; renaming
  one is a breaking change.
- Extracted IDs and locations are **repo/root-relative** (relative to the
  `--root` passed), e.g. `internal/store.LoadConfig` at
  `internal/store/store.go:9` — not absolute, not walk-dir-relative. The
  manifest contract keys on this.

### Check semantics worth remembering

- Only **resolved**-confidence extraction can produce error findings; the
  token tier is advisory by construction (and must stay that way — see §g-Q3).
- `location-drift` is info, never a failure: line numbers are derived data.
- Exact-ID pairing happens before canonical pairing because two different
  types with a same-named method (`AllowlistManager.Load` vs
  `PermanentAllowlist.Load`) canonicalize identically — the collision is
  deliberate and documented in `internal/match/collision_test.go`.
- `_test.go` files are never manifest sites; any path containing `/testutil/`
  is flagged `testinfra`. The walk skips dot-dirs, `vendor`, `node_modules`.
- Default scan dirs: `cmd` and `internal` (override with `--dirs a,b`). A
  narrowing that excludes declared sites adds a `scope-hint` info naming the
  flag as the cause.
- The CI facts-freshness gate ignores the audit `commit:`/`date:` lines via
  `git diff -I` (`-I'^[[:space:]]*commit:' -I'^[[:space:]]*date:'`): those
  two lines legitimately drift because HEAD always moves between the
  manifest-refresh commit and the CI run. Do not "simplify" them away —
  without them the gate is structurally red.
- Baseline lifecycle is enforced: an entry suppressing nothing today warns
  (`unused-baseline` — only-shrinks), an expired `expires:` date fails
  (`baseline-expired`, error). The canonical-key hiding of two same-base-name
  sites behind one entry remains — the warning is the guardrail, not a fix.

## Testing patterns

- `testdata/extract/` is a fixed miniature tree (`cmd/app`, `internal/store`)
  shared by `internal/extract` and `internal/check` tests. Tests reference
  sites by repo-relative ID; determinism is asserted.
- `testdata/detectors/` is the SECOND miniature tree: deliberately bug-shaped
  code for detector tests, kept OUT of the manifest contract on purpose (the
  scaffold round-trip asserts severity-clean lint on the clean tree only).
  It never compiles (testdata is invisible to the go tool) — parseable is the
  only requirement. Lint output is byte-pinned by goldens
  (`cmd/io-surface/testdata/lint-*.golden`); intentional output changes
  re-run `go test ./cmd/io-surface -run TestGolden -update`.
- `internal/scaffold`'s test is the round-trip proof: copy fixture → extract →
  scaffold → `manifest.Load` → `check.Run` → `render.Markdown`, and the check
  must be green (green-by-construction guarantee).
- `cmd/io-surface` has direct e2e tests (`main_test.go`): every test drives
  the real cmdguard execution via `runApp` (flag structs, parsing, handlers)
  with a swappable `stdout` sink, plus the `exitCode` 0/1/2 table. **No direct
  tests** exist for `internal/manifest` and `internal/render` (only exercised
  via scaffold's test) — known gap, tracked in TODO_LIST.
- Table-driven stdlib tests, no external test framework, no mocks (the tool is
  hermetic; keep it that way).

## Conventions

- Package doc comments are load-bearing: every internal package opens with a
  rationale-explaining doc comment (why hermetic, why tiers, why pairing
  order). Extend those comments when changing the design rationale — they are
  the architecture documentation.
- Go code: gofmt-clean, tabs, stdlib-first. Errors wrap context
  (`fmt.Errorf("…: %w", err)`); sentinel errors live in per-package
  `errors.go`.
- errcheck policy (decided 2026-11-08, TODO #123): stdout/stderr report
  writes are deliberately unchecked and carry `_, _ =` at the site — the
  exit-code contract (0/1/2) reflects the GATE result, never a printer
  hiccup, and a piped reader closing early kills the process via SIGPIPE per
  Go runtime convention (the correct CLI behavior). No `.golangci.yml` exists
  by design and CI does not run golangci-lint; do not "fix" the `_, _ =`
  sites or add a config without reopening the decision. Everything else
  (real error returns, including test helpers like `fmt.Sscanf` parses) is
  checked.
- Manifest editing: `facts.cue` is mechanical (regenerate, never hand-edit
  locations); `claims.cue`/`baseline.cue` are human judgment (never overwrite).
  `schema.cue` is the standard copy — do not edit per repo (except here, where
  the source of truth is `internal/scaffold/schema.cue`).
- `cue` binary is never needed at runtime or for tests; `cue fmt` is only a
  hand-editing habit.
- CHANGELOG follows Keep a Changelog; version const in `cmd/io-surface/main.go`.
- Every health/report claim names its verifying command ("verified how" is part
  of the claim — a number or state without the command that produced it is
  unverified and says so).
- Docs ownership: `README` (users) / `AGENTS` (agent context) / `FEATURES`
  (status inventory) / `TODO_LIST` (open work) / `ROADMAP` (vision, open
  questions) — one fact, one home.
